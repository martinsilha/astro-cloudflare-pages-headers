# 2.0.0 — Astro 4–7 and Cloudflare Workers

This is a breaking release that moves the package from source-only integration loading to compiled ESM and declarations, and adds runtime response headers for the official Cloudflare adapter.

- The declared Astro peer range is stable Astro 4–7. Cloudflare adapter versions remain constrained by each adapter's Astro peer range.
- Cloudflare adapter projects enable runtime middleware automatically. It fills missing response headers; application-set values win. Set `runtime: false` to opt out while retaining static `_headers` output.
- A universal `*` route normalizes to `/*` without the old `workers: true` switch. The option remains accepted but is deprecated.
- Prefer `headers` for integration-owned rules. If omitted, final `server.headers` remains a backward-compatible source; an explicit empty object disables inherited rules.
- Existing `_headers` content is preserved and generated content is updated in place. Invalid rules, uncertain Cloudflare output paths, required I/O failures, and Cloudflare line/rule overflows now fail builds by default.
- CSP hashing remains build-time only. Wildcard fallbacks and native Astro CSP are preserved; runtime pages must produce policies for their own dynamic inline content.

Compatibility claims should be read alongside the exact pinned rows and CI results in the compatibility workflow. This source note does not claim production deployment, npm publication, every adapter release, third-party adapters, prereleases, or Astro versions beyond 7.
